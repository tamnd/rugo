# Changelog

What each release changed, why, and what it costs you. The versioning rules and what a section has to contain are in [RELEASING.md](RELEASING.md).

While the major is 0, a minor release may break anything, including the wire protocol and the command set.

Any number in here carries the machine and the profile it was measured on, or it does not go in. Nothing in this file was measured on a laptop.

## 0.1.0 — unreleased

Milestones `M0`, `M1` and `M2`: the workspace, the map and the server. This is the first version that can be measured, and it has not been measured against anything yet.

### Added

- **A sharded Swiss table with a slab arena underneath it, in `rugo-map`.** One control byte and one four byte arena offset per slot, which is five bytes against the ten a Robin Hood bucket of one distance byte, three hash bytes and a six byte pointer costs. Probing is sixteen slots at a time under NEON, sixteen under SSE2 and eight at a time word-at-a-time everywhere else, so the narrower metadata is not a trade against speed. Entries are packed head to tail in a per-shard arena addressed by `u32` with no allocator header, which is the eight to sixteen bytes a `malloc` per entry costs. Key and value lengths are varints, and the expiry and the user flags are only there when a header bit says they are, so the ordinary entry header is three bytes.
- **A memory test that is a gate rather than a claim.** `crates/rugo-map/tests/memory.rs` fills the map at several sizes and shard counts and fails if the index costs more per entry than the design allows. It runs on every push, in release, with the figures printed into the log.
- **A RESP2 and RESP3 server, in `rugo-server`.** `GET SET SETEX PSETEX MGET MSET INCR DECR INCRBY DECRBY STRLEN DEL UNLINK EXISTS EXPIRE PEXPIRE EXPIREAT PEXPIREAT TTL PTTL PERSIST DBSIZE FLUSHALL FLUSHDB PING ECHO HELLO SELECT RESET QUIT INFO COMMAND CONFIG GET CLIENT`, over TCP and over a unix socket, with inline commands and pipelining. `SET` takes `EX PX EXAT PXAT KEEPTTL NX XX GET`. RESP2 and RESP3 differ in exactly two places, the null and the map, and both are tested byte for byte in `crates/rugo-server/tests/wire.rs`.
- **N threads, each with its own poller.** epoll on Linux, kqueue on the BSDs and macOS, level triggered, with the listeners in every thread's poller so whoever is free takes the connection and keeps it. `std` owns the accept, the read and the write; the unsafe is confined to the multiplexing syscall itself.
- **`SCOREBOARD.md`, generated by `cargo xtask scoreboard`.** It is written from the sweep files committed in `bench/` and checked on every push, so a ratio cannot be typed in by hand. It currently says that no sweep has been published, which is the honest state rather than an empty table that looks like a result.

### Known gaps

- **No published numbers.** rugo builds, passes its tests and serves, and that is a different claim from being faster than anything. The two bench hosts are not provisioned and rugo is not yet a subject in `cache-bench`.
- **No memory numbers against a rival.** `cache-bench` measures throughput, latency and CPU cycles and does not measure memory anywhere. Until `cb-mem` lands there, the memory half of the goal is asserted against this project's own design and against nobody else's.
- **`--uring` is accepted and does nothing.** The io_uring backend is `M5`.
- **One eviction rule and no choice of rule.** Under `--maxmemory` the map draws two entries at random and drops whichever expires sooner, an entry with no expiry counting as expiring last. That is a deliberate trade — a true recency order costs two links an entry, and sixteen bytes of links on a five byte slot would undo the thing this map exists for — but it is one rule where Redis offers eight, and `maxmemory-policy` is not settable. Whether it is the right rule is a question for a sweep.
- **No authentication and no TLS.** `M6`.
